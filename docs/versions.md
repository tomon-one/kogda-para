# Как называются версии

Версия `pr-Зерно.0.1.0` читается слева направо:

- `pr` — стадия: `b` — бета, `pr` — пре-релиз, `r` — релиз;
- `Зерно` — имя выпуска;
- первая цифра — крупный релиз: то, ради чего стоит рассказать всем;
- вторая — крупный патч: заметные изменения, новые возможности;
- третья — мелкий патч: правки вёрстки, текстов, одиночные ошибки.

Буквы впереди говорят, чего ждать: `b` — приложение ещё меняется и может
сломаться, `pr` — почти готовая версия: раздаётся группе, крупных изменений
больше не будет, только исправления ошибок и небольшие улучшения; `r` —
версия, которую не стыдно раздать кому угодно.

## Имена выпусков

Имя меняется вместе со второй цифрой — крупным патчем. Слова короткие,
в два-три слога: длинное имя не влезает в строку и не запоминается.

Тема имён меняется с крупным релизом — и со сменой буквы.

**pr, 0.1–0.9 — прорастание. Порядок держит рост: от зерна к плоду**

| | | | |
|---|---|---|---|
| 0.1 Зерно | 0.2 Росток | 0.3 Всход | 0.4 Побег |
| 0.5 Лист | 0.6 Бутон | 0.7 Цвет | 0.8 Завязь |
| 0.9 Плод | | | |

Первая — сборка 1, `pr-Зерно.0.1.0` (27.09.2026). По имени видно, сколько до
релиза: из «Плода» выходит `r-Алтай.1.0.0`, а крупных переделок, которым не
хватит девяти имён, в пре-релизе быть не должно.

До 27.09.2026 счёт был другим (`b-…` на 0.x, `pr-Зерно.0.10` и дальше, сборки
до 86-й). Имя вне схемы выше, `b-` при нуле впереди и `0.10` и дальше
приложение считает прежним счётом и не ставит (`olderNumbering` в
`AppUpdate.kt`).

**1.x — то, что на карте не двигается: реки и горы. С «А» и по алфавиту**

| | | | |
|---|---|---|---|
| 1.0 Алтай | 1.1 Байкал | 1.2 Витим | 1.3 Голец |
| 1.4 Дон | 1.5 Енисей | 1.6 Жигули | 1.7 Зея |
| 1.8 Иртыш | | | |

Одна тема на всю ветку, а не «что-нибудь твёрдое»: иначе в список попадают
слова разной природы и синонимы.

С релиза алфавит соблюдается без пропусков: по имени видно, что новее, как
у выпусков Ubuntu. Первый релиз — `r-Алтай.1.0.0`, его патчи — `r-Алтай.1.0.1`,
`r-Алтай.1.0.2`. Крупный патч меняет имя: `r-Байкал.1.1.0`.

## Tested

Новое сначала проверяется на tested-сборке — отдельном приложении
«Когда пара? tested» (`ru.whensclass.tested`), которое стоит рядом с
основным. Обновления она берёт со своего канала сервера
(`/v1/app?channel=tested`), на GitHub её нет.

- Перед работой над новым `versionCode` и `versionName` поднимаются до
  будущей основной версии.
- Tested-сборка — `./gradlew assembleCandidate` (имена на «test» Gradle не
  разрешает). Её номер — `versionCode × 100 + TESTED_TRY`, имя —
  `versionName-tTESTED_TRY`: 501 и `pr-Зерно.0.1.4-t1`. Следующая tested —
  `TESTED_TRY` плюс один.
- Проверено — та же версия выходит основной сборкой (номер 5), а `TESTED_TRY`
  снова 1.

## Номер сборки

Кроме имени есть простой счётчик — `versionCode`. Он растёт на единицу с
каждой выложенной сборкой и не повторяется — кроме одного раза: 27.09.2026
счёт начат заново с 1 (выше). По нему приложение
понимает, что на сервере лежит версия новее установленной. Имя для этого не
годится — сравнивать слова машина не умеет. По нему же называется файл на
сервере: в имени версии бывают русские буквы, а адрес с ними не открывается.

## Где менять

`android/app/build.gradle.kts`:

```kotlin
versionCode = 4                  // то, что стояло, плюс один
versionName = "pr-Росток.0.2.0" // по правилам выше
```

Числа здесь для примера, текущие — в самом файле.

## Сайт

Версия сайта — `веб-0.1.1`: те же три цифры, без стадии и имени; поднимается,
когда меняется то, что видит человек. Какие именно файлы выложены, говорит
номер сборки — первые 12 знаков хэша файлов; и то и другое видно в
«Настройки» → «О сайте». Новое, как у приложения, сначала выкладывается на
`kogda-para-nsk.ru/tested/`, на основной адрес — после проверки.
