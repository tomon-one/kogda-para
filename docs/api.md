# Контракт API

Базовый адрес на боевом сервере — `https://schedule.edelweiss-alpine-confederation.ru`,
при локальной разработке `http://127.0.0.1:8081`.

Версия в пути (`/v1/`). Приложение, которое уже стоит у людей на телефонах,
обязано продолжать работать: ломающие изменения — только новой версией пути.

## Правила, на которые опирается приложение

- **Пустого поля в ответе нет вовсе.** Не `"r": null`, а отсутствие ключа.
- **`"l": []`** — день есть, пар нет. Виджет пишет «пар нет».
- **Дня нет в `days`** — этой даты в листе нет. Причин две, и приложение их
  различает по `cov`: если дата внутри покрытия, это выходной (воскресений в
  листах колледжа не бывает) и виджет пишет «выходной»; если снаружи — колледж
  ещё не выложил, и виджет пишет «ещё не опубликовано». Раньше на оба случая
  отвечали вторым, и воскресенье выглядело неопубликованным навсегда.
- **`cov`** — какие даты покрывает лист. По нему приложение понимает, что пора
  спросить сервер про новую неделю.
- **Идентификатор группы неизменен.** Он лежит в настройках на телефоне;
  правила транслитерации в `server/src/whensclass/domain/ids.py` менять нельзя.
  `ИСП-924/2` → `isp-924-2`, `01-26.РКИ.ОФ.9` → `01-26-rki-of-9`.
- Колонка вида `ДП-923 и ДП-1124` даёт **две группы с одинаковым расписанием**.
  Обе есть в `/v1/groups`.

## Эндпоинты

### `GET /v1/meta`

Самый дешёвый запрос. Если `gen` не изменился с прошлого раза, расписание
качать незачем.

```json
{"v":1,"gen":"2026-09-07T10:29:53Z","src":"расписание групп 01.-05.09",
 "groups":187,"status":"ok","cov":["2026-09-02","2026-09-12"],
 "checked":"2026-09-07T10:29:28Z"}
```

`status`: `ok` — данные свежие; `stale` — таблица не читается или изменила
формат, отдаётся прежний снимок; `empty` — сервис ещё ничего не разобрал
(тогда ответ 503). `checked` — когда сервер последний раз ходил в таблицу,
`gen` — когда он в последний раз получил из неё новые данные. Эти времена
расходятся, и это нормально: таблицу перечитывают чаще, чем она меняется.

Ответ намеренно без `ETag` и без кэширования: это тот запрос, которым
спрашивают «а не изменилось ли», и кэшировать его бессмысленно.

### `GET /v1/groups`

```json
{"v":1,"gen":"...","groups":[{"id":"isp-924-2","name":"ИСП-924/2"}]}
```

### `GET /v1/schedule/{group_id}?from=2026-09-07&days=3`

Главный запрос виджета. `from` по умолчанию сегодня, `days` — 3, допустимо
1–14. Приложение просит семь дней от понедельника текущей недели: прожитые дни
остаются на экране, а неделя целиком нужна недельному виджету.

```json
{"v":1,"g":"isp-924-2","gn":"ИСП-924/2","gen":"2026-09-07T10:29:53Z",
 "src":"расписание групп 01.-05.09","cov":["2026-09-02","2026-09-12"],
 "bells":{"1":["08:30","10:00"]},
 "days":[{"d":"2026-09-08","l":[
   {"n":4,"s":"Иностранный язык","k":"Пр","t":["Старостина Е. А."],"r":"272"},
   {"n":2,"s":"UX/UI дизайн","k":"Лек","x":1,"c":"преподаватель заболел"},
   {"n":6,"s":"Информатика","k":"Лек","u":"https://my.mts-link.ru/j/..."}]}]}
```

Поля пары:

| ключ | смысл |
|---|---|
| `n` | номер пары |
| `s` | предмет |
| `k` | тип занятия: `Лек`, `Пр`, `Курс.р.` … |
| `t` | преподаватели, список |
| `r` | аудитория |
| `u` | ссылка на вебинар вместо аудитории |
| `x` | `1`, если пара отменена |
| `c` | причина отмены, если в таблице написали |
| `gr` | чья это пара. В расписании преподавателя — группа, которой он читает; в расписании группы появляется только у пар, пришедших из второй подгруппы |

`bells` появляется, только когда сетка звонков известна серверу. Пока её нет,
виджет показывает номера пар без времени — выдумывать время нельзя.

404 — группы нет. 503 — сервис ещё не разобрал таблицу.

### `GET /v1/teachers`

Список преподавателей. Собирается переворотом того же снимка: в таблице
колледжа своего расписания у преподавателя нет, оно рассыпано по колонкам
групп.

```json
{"v":1,"gen":"...","teachers":[{"id":"averkova-anna-sergeevna",
                                "name":"Аверькова Анна Сергеевна"}]}
```

Идентификатор строится из фамилии и инициалов теми же правилами, что и у
групп, и так же неизменен — он лежит в настройках на телефоне.

### `GET /v1/teacher/{teacher_id}?from=2026-09-08&days=7`

То же, что расписание группы, с двумя отличиями: есть `"kind":"teacher"`,
у пар нет `t` (преподаватель и так известен), зато есть `gr` — кому читается
пара. Приложение показывает такое расписание тем же кодом, что и обычное,
поэтому виджеты и напоминания работают у преподавателя без отдельной ветки.

404 — такого преподавателя в снимке нет.

### `GET /v1/app`

Последняя выложенная сборка приложения. Магазина нет, поэтому приложение
сравнивает свой `versionCode` с этим и предлагает обновиться.

```json
{"v":1,"versionCode":35,"versionName":"b-Эхо.0.4.2",
 "url":"https://schedule.edelweiss-alpine-confederation.ru/download/kogda-para-35.apk",
 "size":2588960,"notes":"приложение само замечает новую сборку"}
```

Сравнивается именно `versionCode` — целое число, которое растёт с каждой
выложенной сборкой. `versionName` человеку показывают, машине он не годится.
404 — сборка ещё не выкладывалась. Кэширования нет: узнать об обновлении надо
сразу, а не через пять минут.

Файл раздаёт nginx по адресу из `url` (`/download/<имя>`), минуя службу. Имя
файла содержит номер сборки и состоит только из латиницы: в имени версии
бывают русские буквы, а адрес с ними ломается. Данные для этого ответа кладёт
`tools/publish_apk.py`.

### `GET /healthz`

`{"ok":true,"status":"ok"}`, код 503 пока снимка нет.

## Кэширование

Ответы несут `ETag`, посчитанный по телу. Повторный запрос с `If-None-Match`
получает `304` и ноль байт. Исключение — `/v1/meta` и `/v1/app`: их спрашивают
именно затем, чтобы узнать об изменении, и кэшировать их нечего. `Cache-Control: public, max-age=300,
stale-while-revalidate=3600`. Типичный ответ на три дня — около 1.7 КБ,
против 820 КБ исходной таблицы.
